Working with Microsoft 365

A practical guide to where your files live, how to open and share them, and what to do differently now that the office file server has been replaced by Microsoft 365.

For all agency staff · Updated May 27, 2026

The office is transitioning shared files off the local file server and onto Microsoft 365. The change is mostly transparent: files open the same way, save the same way, and look the same in File Explorer. A few things are genuinely better — you can now edit the same spreadsheet at the same time as a colleague without locking them out, and accidentally deleted files can be recovered for 93 days. A few things are different and worth knowing in advance. This guide covers both.

The three tools and what each is for

Microsoft 365 includes three different places that hold files. They look related, and they are, but each has a clear purpose. Knowing which is which will save you confusion.

SharePoint
Shared office files

This is where everything that used to be on the office file server now lives. Anything your colleagues need to see — policies, claim files, accounting, shared spreadsheets — lives in SharePoint.

OneDrive
Your personal cloud drive

The cloud equivalent of your old “My Documents” folder. Files here are visible only to you (unless you share them). Use it for drafts, personal scratch work, or anything you haven’t shared yet.

Teams
Chat and file sharing

Microsoft Teams handles chat and meetings. When you drop a file into a Teams channel, the file actually lives in a SharePoint library behind the scenes — Teams is just a faster way to find it.

Simple rule

If your colleagues need to see it, save it in SharePoint. If only you need it, save it in OneDrive. If you’re chatting about a file with someone, drop it in Teams — it will land in the right SharePoint library automatically.

Where the shared files now live

The office’s SharePoint site is organized into document libraries, one for each part of the business. Think of each library as the equivalent of one folder on the old file server — but with proper permissions, version history, and the ability for multiple people to edit at once.

You will see libraries appropriate to your role. A typical staff member sees some combination of:

  • Producers — new‑business work, applications in progress, prospect material
  • Claims — active and closed claim files, carrier correspondence
  • Underwriting — binders, declarations, endorsements, policy archives
  • Accounting — commission statements and agency financials
  • Admin — HR, licensing, E&O, vendor records

If you don’t see a library you used to have access to, ask the agency administrator. Access is set per‑library by your role, the way the old folder permissions worked — but now it’s explicit instead of inherited from a network share.

Opening files the way you always have

The big change is what replaces the mapped H:\ (or similar) drive on your computer. Instead of a network drive letter, your SharePoint libraries appear in File Explorer under your OneDrive folder.

To set this up the first time:

  1. Open Microsoft Edge (or any browser) and sign in to office.com with your work email.
  2. Click SharePoint in the app launcher, then open the agency team site.
  3. For each library you want in File Explorer, click Documents at the top, then click Add shortcut to OneDrive. (Microsoft’s instructions, with screenshots.)
  4. Open File Explorer on your desktop. The shortcut will appear under your name in the left‑hand pane, inside the cloud‑icon “OneDrive” entry.

From that point on, opening a shared file looks exactly like it always did:

File Explorer → OneDrive — Agency → Claims → 2026 → Smith.xlsx

Double‑click a file and it opens in Excel, Word, or whichever app handles that file type. You can use the new system the same way you used the file server.

About the cloud icons next to filenames

Files in OneDrive have a small icon next to them in File Explorer. A blue cloud means the file lives in the cloud and downloads on demand when you open it. A green checkmark means it’s also stored locally on your computer. If you know you’ll need a file while offline, right‑click it and choose Always keep on this device.

Saving, autosave, and version history

Autosave is on by default

When you open an Office file (Word, Excel, PowerPoint) that lives in SharePoint or OneDrive, you’ll see an AutoSave toggle in the top‑left corner of the app. It will be on automatically. Your changes save continuously as you type — you do not need to press Ctrl+S.

If you prefer the older behavior, you can turn AutoSave off for an individual file. Most people leave it on after a day or two.

Version history

Every file keeps a history of approximately 500 prior versions. If you need to undo a change someone made yesterday, or recover a previous version of a spreadsheet:

  1. Right‑click the file in File Explorer (or on the web) and choose Version history.
  2. Browse the list of saved versions by date and editor.
  3. Open any version to preview it, or restore it as the current copy.

Recovering deleted files

If you delete a file by accident, it goes to the SharePoint Recycle Bin for 93 days. The administrator can recover it from there at any point in that window. Beyond 93 days, the agency’s separate backup system can recover the file from a longer‑term copy.

Editing Excel at the same time as a colleague

One of the most useful improvements: you can now edit the same Excel file as a colleague at the same time. No more “Locked by another user” messages on shared workbooks.

When you open a file that’s also open by someone else, you’ll see their initials at the top of the Excel window, and their cursor will appear inside the spreadsheet as you both work. Changes flow back and forth in real time. (Microsoft’s reference, with examples.)

Macro‑enabled spreadsheets behave differently

Files ending in .xlsm (workbooks with macros) cannot be co‑edited. If you open one, you may see a “file locked by” notice if someone else has it open. For these files, only one person can edit at a time — the same way it worked on the file server. If you frequently share a macro‑enabled file, talk with the agency administrator about whether the macros can be converted or replaced.

Sharing files with colleagues and clients

Inside the office

You usually don’t need to share files with colleagues explicitly — if they have access to the same library, they already see the file. Just tell them where it is.

Outside the office

To share a file with a client, carrier, or other outside party:

  1. Right‑click the file in File Explorer (or click the Share button in Excel/Word).
  2. Choose Share → OneDrive or the SharePoint sharing dialog.
  3. Enter the recipient’s email address. Choose whether they can view only or edit.
  4. Click Send. The recipient gets an email with a link that opens the file in their browser.
Recipients do not need a Microsoft 365 account

External recipients can view and edit files in their browser without signing up for anything. They will receive a verification code by email the first time they open the link.

Avoid email attachments where possible

For files that live in SharePoint or OneDrive, sharing a link is preferable to sending an attachment. The recipient always sees the latest version, the link can be revoked, and the file does not duplicate across mailboxes. Excel and Word will offer to send a link instead of an attachment when you use File → Share.

Working without an internet connection

You can work on cloud files even when your internet is out, with one preparation step.

If you know you’ll be working away from the office, or want a particular folder available regardless of connection, right‑click the file or folder in File Explorer and choose Always keep on this device. The cloud icon next to it changes to a green checkmark, and the contents are stored locally on your laptop.

Changes you make offline are saved locally. When your connection returns, OneDrive automatically uploads the changes to the cloud. If you and a colleague both edited the same file offline, OneDrive will create a conflict copy with both names so nothing is lost.

A few things to avoid

Do not move Outlook PST files into OneDrive or SharePoint

If you have an old Outlook archive file (.pst), do not drag it into your OneDrive or any SharePoint library. Outlook keeps these files open in a way that breaks cloud sync and can corrupt the file. If you need to archive old mail, ask the agency administrator about importing it into your mailbox instead.

Be careful with very long folder paths

SharePoint has a 400‑character limit on the full path to a file. If you create folders inside folders inside folders, you can eventually exceed this and files become unsavable. Keep folder structures reasonably shallow — three or four levels deep, not seven or eight.

Avoid certain characters in filenames

SharePoint does not allow the following characters in filenames: " * : < > ? / \ |. If you try to save a file with one of these, Office will warn you and offer to rename it.

Common questions

What happens if my internet goes out in the middle of editing?

Office will continue to let you edit and save the file locally. When your connection returns, your changes upload automatically. If a colleague edited the same file while you were offline, you will see a notice and OneDrive will reconcile the changes — in rare cases creating a conflict copy with both versions so nothing is lost.

How do I see who else is editing a file right now?

In Excel, Word, and PowerPoint, the initials of other active editors appear in the top‑right of the window. Click on the initials to see who they are. You can also see their cursor moving inside the document in real time.

Can I still print, save as PDF, and email files the way I always have?

Yes. The Office apps work identically. Printing, exporting to PDF, sending as an attachment from Outlook, and copy‑pasting between documents all work the same way they did when files lived on the file server.

I accidentally deleted a file. How do I get it back?

Go to the SharePoint library in your browser, open the library, and click Recycle bin in the left menu. Find the file, click Restore. Items stay in the recycle bin for 93 days. If you need a file that was deleted longer ago, the agency administrator can recover it from the backup system.

What about the files in my old “My Documents” folder?

Personal documents that only you need belong in OneDrive, not SharePoint. OneDrive is your personal cloud space. You can drag the contents of your old Documents folder into OneDrive, or ask the agency administrator to migrate them for you. Anything that needs to be visible to colleagues should go into the appropriate SharePoint library instead.

Will my Excel files with macros still work?

Yes — macros run normally when you open an .xlsm file from SharePoint in the Excel desktop app. The only limitation is that macro‑enabled files cannot be co‑edited by multiple people at once. They open as “locked” when someone else has them open, the same as on the old file server.

Do I have to log in every time?

No. Once your Office apps and File Explorer are signed in with your work account, you stay signed in. You will be asked to confirm your identity with multi‑factor authentication periodically (typically every few weeks, or when accessing from a new device or location).

What if I have a file open and the power goes out on my computer?

If AutoSave was on, all your changes up to the moment of power loss were saved to the cloud. When you sign back in, the file will be in its most recent state. If AutoSave was off, Office may recover unsaved changes from a temporary file when you reopen the app — the same recovery process you may remember from older versions of Office.

I’m getting a multi‑factor authentication prompt. What is that?

Multi‑Factor Authentication (MFA) adds a second check beyond your password — typically a code from your phone or an approval in the Microsoft Authenticator app. This is required for the agency’s security and is standard across the insurance industry now. If you have not set up MFA yet, the agency administrator can walk you through it.

Getting help inside the agency

For agency‑specific questions — access to a library, where a particular file is, what to do with a file you’re not sure about — ask the agency administrator. They have the broader view of how the system is configured and can answer questions Microsoft’s training cannot.

For general “how does this feature work” questions, the Microsoft training above will usually be the fastest path to an answer.
