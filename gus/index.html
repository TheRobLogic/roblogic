Migration Brief / Recommendation

Microsoft 365 as a File Server Replacement

A recommendation brief for a small insurance agency moving from an on‑premises Windows file server to cloud‑based shared storage, with a local backup tier for resilience and compliance.

Prepared May 27, 2026 Audience: Agency Principal Scope: ~5–15 staff, California
Read recommendation Staff orientation guide →

Executive Summary

The recommendation is to retain Microsoft 365 as the day‑to‑day collaboration platform and use SharePoint Online for shared business files, with three discrete changes from the current posture:

  1. Upgrade the existing Microsoft 365 subscription to Business Premium to unlock the security and compliance features required by the Gramm‑Leach‑Bliley Safeguards Rule and by appointing carriers.
  2. Stand up a single SharePoint team site with document libraries organized by business function, accessed by staff through the OneDrive sync client.
  3. Deploy a Synology NAS on the local network as a backup tier, running Active Backup for Microsoft 365 and replicating offsite to Backblaze B2.

The combined architecture closes the gap exposed by the recent server failure (no resilient local backup, slow recovery path), satisfies the cybersecurity controls expected by carriers and E&O underwriters, and avoids the cost and switching pain of moving off Microsoft 365.

Bottom line

Stay on Microsoft 365 for live work. Add a Synology for backup and rapid recovery. Total incremental cost: roughly $95/month in subscription delta (10 users) and $1,200–2,000 one‑time in hardware. Estimated migration window: one weekend.

Recommended Architecture

The architecture has three layers, each with a distinct purpose:

Layer 1 — Live
SharePoint
Where staff open, edit, and co‑author files every day. One team site, multiple document libraries by function.
Layer 2 — Local Backup
Synology NAS
Nightly tenant‑wide backups, weekly workstation images, immutable Btrfs snapshots. Fast restore path.
Layer 3 — Offsite
Backblaze B2
Encrypted, immutable, geographically separate copy. Satisfies the 3‑2‑1 expectation in carrier security questionnaires.

Staff interact only with Layer 1. Layers 2 and 3 operate automatically and are touched only during recovery or audit.

Live Storage — Microsoft 365 SharePoint

Site and library structure

A single SharePoint team site for the agency, containing one document library per business function:

  • Producers — new‑business files, applications in progress, prospect material
  • Claims — active and closed claim files, carrier correspondence
  • Underwriting — binders, declarations, endorsements, policy archives
  • Accounting — commission statements, agency financials, vendor records
  • Admin — HR, licensing, E&O, vendor contracts, agency operations

Permissions are managed at the library level using Microsoft 365 groups, not on individual folders. For an agency this size, a hub site or multi‑site architecture is not warranted — one team site is the right answer. (See Microsoft’s SharePoint hub site planning guidance.)

How staff reach the files

Each staff member uses the OneDrive sync client (already installed with Microsoft 365) and the “Add shortcut to OneDrive” feature on each library they need access to. The libraries then appear inside File Explorer under the user’s OneDrive folder — the same muscle memory as a mapped H:\ or S:\ drive. Files are streamed on demand, with the option to pin specific files or folders for offline use.

Co‑authoring on Excel

Standard .xlsx files support real‑time multi‑user editing in SharePoint and OneDrive, with autosave on and approximately 500 versions of history retained per file (Microsoft documentation). The era of “Sheet locked by another user” is over for plain workbooks.

Macro‑enabled workbooks behave differently

Files with VBA macros (.xlsm, .xlsb) do not support co‑authoring. Users will see “Locked by another user” prompts and macros will not run in Excel for the web. Where practical, convert macro spreadsheets to .xlsx. Where macros are essential, treat those workbooks as single‑user‑at‑a‑time. (Microsoft troubleshooting reference.)

Backup Tier — Synology NAS

SharePoint’s version history and 93‑day recycle bin are recovery features, not a backup. They do not protect against ransomware that encrypts files (encrypted versions are saved over the originals), administrator account compromise with mass deletion, misconfigured retention policies, or the discovery‑after‑the‑fact deletion that exceeds the 93‑day window.

For a small office, a Synology NAS on the local network provides this protection at low cost and low complexity. The recommended configuration:

  • Synology DS923+ (~$600) with two 8 TB IronWolf drives in SHR (Synology Hybrid RAID, single‑drive redundancy)
  • A small UPS (~$200) to protect against power events
  • Active Backup for Microsoft 365 (free Synology package) configured to back up the entire M365 tenant nightly
  • Active Backup for Business (free Synology package) configured to image every staff workstation weekly
  • Hyper Backup replicating to Backblaze B2 (~$6/TB/month) for offsite, immutable copies
  • Btrfs snapshots configured for short‑interval, immutable point‑in‑time recovery

Migration Plan

The recovered file server data should be migrated using Microsoft’s free SharePoint Migration Tool (SPMT). SPMT runs on Windows, accepts a local folder or UNC path as a source, preserves file Modified dates, and handles the path/character validation that hand‑copying cannot.

Phase 1 — Destination preparation

  1. Upgrade the existing tenant to Microsoft 365 Business Premium
  2. Create the SharePoint team site with the library structure listed above
  3. Configure Microsoft 365 groups for each library’s access control
  4. Enable Multi‑Factor Authentication tenant‑wide (Conditional Access)
  5. Set external sharing default to “Specific people”, disabling anonymous links (see external sharing settings)
  6. Configure Microsoft Purview retention policies for the agency’s document retention requirements
  7. Enable Unified Audit Log (default on new tenants; verify) and extend retention via custom policy

Phase 2 — Source preparation

  1. Run SPMT pre‑scan against the recovered drive to surface every long path and invalid character
  2. Remediate flagged paths (rename, shorten, or restructure folders)
  3. Separate problem file types into a holding area: .pst, .accdb, .mdb, password‑protected Excel, workbooks with linked references
  4. Decide disposition for each problem type (see next section)
  5. Repair or document Excel linked‑workbook references before migration

Phase 3 — Migration execution

  1. Run SPMT against each top‑level folder, targeting the matching SharePoint library
  2. Schedule migration during off‑hours (Microsoft throttles cloud uploads during business hours; see migration speed reference)
  3. Review the SPMT report after each batch; address skipped files
  4. Validate that Modified dates were preserved (sort by Modified column, spot‑check 10–20 files)
  5. Verify total file count and aggregate size match source

Phase 4 — Workstation cutover

  1. Add OneDrive shortcuts to each library on each staff workstation
  2. Remove or remap the old H:\ drive references
  3. Update any Excel workbooks with file paths to reference the new SharePoint locations
  4. Stand up the Synology NAS and configure backup jobs
  5. Brief staff using the orientation guide

Problem File Types

Never place Outlook PST files in OneDrive or SharePoint

Microsoft explicitly excludes .pst files from supported OneDrive content. Outlook holds these files open with continuous writes that the sync engine cannot reconcile, resulting in corruption. A January 2026 Windows update made the failure mode worse, with reports of PST corruption when stored in OneDrive. Archive historical email by importing the PST into the user’s M365 mailbox or Online Archive, or store PSTs on an encrypted external drive outside the sync scope. (Microsoft guidance.)

Microsoft Access databases (.accdb, .mdb)

Access databases do not function correctly in SharePoint document libraries because the file‑locking model required by Access is incompatible with how SharePoint handles concurrent access. Four options, ranked:

  1. Migrate to Dataverse — if the database is actively used and has logic worth preserving. (Microsoft migration guide.)
  2. Export to SharePoint Lists — if the database is essentially tables with simple queries. (Microsoft reference.)
  3. Migrate to SQL Server (or Azure SQL) with the Access front‑end retained — if the application logic is complex and rebuilding it is impractical.
  4. Keep on a single workstation as a read‑only archive — if the database is no longer actively used.

Password‑protected Excel workbooks

Workbooks protected with a workbook‑open password open read‑only in SharePoint and do not support co‑authoring. Replace the password with a Microsoft Information Protection sensitivity label, which provides equivalent or stronger access control while preserving full collaboration features.

Excel files with linked workbook references

Workbooks containing formulas that reference other files by path (=[Premiums.xlsx]Sheet1!A1 or absolute paths to \\server\share\...) will not resolve after migration. Two approaches:

  • Repair pre‑migration: Use Data > Edit Links to update each reference to the new SharePoint location. (Microsoft repair guide.)
  • Repair post‑migration: Use the same tool against the migrated files. Lower planning cost, higher per‑file effort.

Both source and destination workbooks must live in the same SharePoint library for linked references to resolve in Excel for the web. Cross‑library and cross‑tenant links will not work.

Alternatives Considered

Dropbox Business or Dropbox Advanced

Approximately $24–30 per user per month, layered on top of an existing Microsoft 365 subscription. Provides nothing the recommended architecture does not already provide, and Excel co‑authoring is supported only when files are in SharePoint or OneDrive — not Dropbox. Not recommended.

Google Workspace

Switching from a Microsoft‑native environment (Outlook, Excel with macros, PDF carrier forms) to Google Workspace incurs substantial retraining and workflow rework, with no compliance or feature advantage for an insurance agency. Not recommended.

Self‑hosted file server replacement

Replacing the failed Windows file server with new on‑premises server hardware reproduces the failure mode (single point of failure, no automatic offsite copy, manual recovery). The recommended Synology NAS provides the on‑premises file‑serving capability while adding immutable snapshots, automated workstation backups, and seamless offsite replication that a traditional file server does not.

Synology as primary, Microsoft 365 for email only

Using the Synology as the primary file‑serving platform with Synology Drive sync clients is technically feasible but sacrifices Excel co‑authoring, SharePoint’s automatic version history, and the deep Office integration that Microsoft‑native organizations expect. The hybrid layered architecture (Microsoft 365 for live, Synology for backup) provides the strengths of each without the trade‑offs.

Action Plan

Week 1

  1. Confirm the current Microsoft 365 plan and upgrade path to Business Premium
  2. Order Synology DS923+, 2×8 TB IronWolf drives, and UPS
  3. Request data‑security exhibits from each appointing carrier and from the E&O carrier to confirm required controls
  4. Inventory the recovered file server data: total size, top‑level folder structure, presence of PST/Access files
  5. Brief staff that a transition is upcoming; share the staff orientation guide

Week 2

  1. Complete the M365 Business Premium upgrade
  2. Create the SharePoint team site and document libraries
  3. Configure Microsoft 365 groups for library access control
  4. Enable Multi‑Factor Authentication tenant‑wide
  5. Configure external sharing defaults and Purview retention policies
  6. Run SPMT pre‑scan against the recovered data; surface and fix path and character issues
  7. Separate PST and Access files for individual handling

Week 3 (cutover weekend)

  1. Execute SPMT migration over Friday evening through Monday morning
  2. Validate file counts, sizes, and Modified dates
  3. Configure each workstation with OneDrive shortcuts to the appropriate libraries
  4. Stand up Synology NAS, configure Active Backup for Microsoft 365, Active Backup for Business, and Hyper Backup to Backblaze B2
  5. Walk staff through the new workflow Monday morning using the orientation guide

Ongoing

  1. Verify backup job success weekly for the first month, monthly thereafter
  2. Test a sample restore quarterly to confirm backups are usable
  3. Review external sharing report monthly to catch inappropriate sharing
  4. Document the written information security program (GLBA requirement)
  5. Schedule annual employee security training
